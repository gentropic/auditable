# Writing the micro manual — style guide

The book: `micro-manual.tex` (LuaLaTeX, KOMA `scrbook`), design in `style/micro.sty`, one file per
chapter in `chapters/`, assembled by `chapters/index.tex`. Build: `node build.mjs` (figures, then
latexmk). Don't compile the whole book while others write; the editor compiles.

## Who reads it

A resource geologist (or a student, or a reviewer of someone's estimate) who knows block models,
drillholes, cutoffs, declustering and swaths, and does NOT know micro. Explain micro, never
geology basics. Respect their time.

## Voice

- Plain, direct, warm, precise. Second person ("you"), present tense, active voice.
- Concrete over abstract: a real column (`FE`), a real menu path, a real number.
- Short paragraphs (2–5 sentences). No marketing words ("powerful", "seamless", "simply",
  "easily", "just"). No exclamation marks.
- Say *why* when it matters to trust ("a blank grade is unestimated, not zero, so it is left out").
- American spelling (color, gray, behavior) — micro's UI uses it.
- Use the demo project's names in examples: `deposit.csv` (XC, YC, ZC, FE, SG, LITO with
  HEMATITE / ITABIRITE / CANGA / WASTE), drillholes DH001…DH012 (collar HOLEID, X, Y, Z, EOH,
  COMPANY — PIONEER or MERIDIAN; assays FE), topography, mining phases 1–3, the ore shell.
  It opens from the empty screen (“open the demo project”) — every reader can follow along.

## Shape of a chapter

```latex
\chapter{Grade–tonnage}\label{ch:gt}
\begin{goals}
\textbf{In this chapter} you … (one or two sentences: what the reader will be able to do).
\end{goals}
Opening paragraph: what the feature is for, in the reader's terms.
\section{…}  % 3–7 sections; subsections sparingly
```

- Lead with the task, then the controls. Every feature: what it answers, how to open it, what each
  setting means, what the result means, pitfalls, how it fits a routine.
- At least one `tryit` box per chapter in Parts I–VI, using the demo project, written as steps a
  reader can do right now.
- Cross-reference generously: `\cref{ch:routines}`, `\cref{sec:gt-units}` (label every chapter
  `ch:…` and important section `sec:…`).
- End a chapter with nothing — no "summary" sections. A short `\section{In a routine}` where the
  feature is a routine tool (give the YAML).

## Vocabulary (macros in style/micro.sty)

| macro | use |
|---|---|
| `\menu{File>Composer…}` | a menu path (`>` separates) |
| `\ui{Run}` | a button, field, tab, checkbox label |
| `\key{⌘K}` | a key cap (`\key{Ctrl}+\key{Z}`); use ⌘ for macOS and note Ctrl on Windows once per chapter at most |
| `\col{FE}` | a column name |
| `\file{deposit.csv}` | a file or folder name/path |
| `\code{abs(x) < 5}` | inline code / an expression / a setting name |
| `\term{grade shell}` | the defining use of a term — goes into the index |
| `\index{…}` | extra index entries (`\index{swath!band width}`) |
| `\side{text}` | a short margin note (outer column) — a hint, a cross-reference |
| `\sidekey{⌘K}{what it does}` | a key in the margin |
| `\new{new}` | a tiny amber marker for something new |

Boxes: `tip` (green, a better way), `note` (blue, a fact worth knowing), `caution` (amber, a trap),
`why` (gray, "why it works this way" — design reasons), `tryit` (violet, a numbered exercise),
`goals` (chapter opener). Don't stack more than two boxes in a row.

Code: `\begin{lstlisting}[language=yaml] … \end{lstlisting}` (also `expr`, `js`). Keep lines under
72 characters. YAML in the block style micro writes (strings quoted where micro quotes them).

Tables: `booktabs` (`\toprule \midrule \bottomrule`), `tabularx` with the `L` column type. Settings
tables: `setting & meaning & default`.

Math: sparingly, `$…$`; units in text (g/t, t/m³, %).

Raw UTF-8 everywhere (— × → · ≥ ≤ ³ ±); never escape them.

## Figures

**Screenshots** are generated by the harness from a live micro, so they never go stale. Write:

```latex
\shot{gt-window}{The grade–tonnage window on the demo deposit: tonnage (left axis) and mean grade (right) above each cutoff.}
```

and add a line to `figures/wanted.txt`:

```
gt-window | the demo project, the deposit's grade–tonnage window with FE and SG, run | window
```

(name | the state to show, precise enough to script | `full` (the whole micro window), `window`
(one floating window), or `region` (describe it)). Names: lowercase-hyphenated, unique, prefixed by
topic (`gt-`, `swath-`, `compo-` …). `\shot[0.6\linewidth]{…}{…}` for a narrower figure.

**Charts from micro's own numbers**: a pgfplots axis reading a TSV the harness produces with
`window.micro.runTool` on the demo project:

```latex
\begin{figure}[htbp]\centering
\begin{tikzpicture}\begin{axis}[width=0.9\linewidth, height=55mm, xlabel={cutoff (\% Fe)}, ylabel={tonnes}]
\addplot[amber, very thick] table[x=cutoff, y=tonnes]{figures/data/gt-demo.tsv};
\end{axis}\end{tikzpicture}
\caption{…}\label{fig:gt-demo}\end{figure}
```

and a line in `figures/wanted.txt`:

```
data gt-demo | {"tool":"gt","params":{"layer":"deposit.csv","series":[{"col":"FE","weight":"SG"}],"cutoffs":[30,40,50,55,60,65]}}
```

(the TSV's columns are the tool's machine table — see `tools/micro/src/tools.js`; e.g. gt →
series, cutoff, tonnes|volume, grade, metal). Colors: `amber`, `info`, `ok`, `sel`, `fault`.

**Diagrams**: TikZ, drawn inline, in the house colors (`rule` lines, `ink` text, `amber` accents,
`tint` fills, `\sffamily\small` labels). Good uses: how micro thinks (elements → columns → views),
a routine's flow, a run folder's anatomy, the section slab, a swath's bands.

## Accuracy

Everything must be true of micro as it is in this repository. Before you describe a control, find
it: `tools/micro/index.html` (menus, COMMANDS), `tools/micro/src/*.js` (each window), the existing
HTML manual `tools/micro/docs/index.html` (a good factual source — rewrite, don't copy), the in-app
help `tools/micro/src/help.js`, and the smokes `test/micro-smoke*.mjs` (they show what really works).
If you can't confirm something, leave it out or mark it `% TODO verify: …` — never invent a menu,
a setting or a number.
